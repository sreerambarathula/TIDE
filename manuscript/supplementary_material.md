# Supplementary Material

## S1. Full governing equations

The complete moving-boiling-boundary dynamical system (general even node count $N_1$) used throughout this study follows the re-derivation of Theler, Clausse and Bonetto [6], itself a from-scratch re-derivation of the original Clausse–Lahey model [2] that removes several intermediate symbols left undefined in the 1991 original. The state vector comprises the boiling-boundary position $\lambda$, the inlet velocity $u_i$, the total two-phase mass inventory $m$, and $N_1/2$ internal node-boundary positions. The steady-state pressure balance (Eq. 26 of [6]) gives the closed-form Euler number:

$$Eu(N_{pch}, N_{sub}; Fr, \Lambda, k_{in}, k_{out})$$

used directly, without approximation, for the fold-curve computation (Section 3.2 of the main text). Full symbolic detail is available in the project code repository (see Data and code availability, main text) in `src/tide/physics/ledinegg_curve.py` (steady-state characteristic) and `src/tide/physics/clausse_lahey.py` (full dynamical system, general even-$N_1$).

## S2. Model verification detail

**Transcription errors found and corrected.** Two errors were found in transcribing the dense friction bracket of the dynamical system's momentum equation, both confirmed against high-resolution page images of the source derivation (not OCR text, which had silently corrupted the relevant fractions in two places): one term had carried over stale symbols from an intermediate derivation step no longer present in the final equation; one term was structurally misplaced outside the bracket it belongs inside. After correction, the steady state obtained from the closed-form Euler-number characteristic satisfies the full dynamical system's steady-state condition to machine precision ($\sim 10^{-15}$) — strong cross-validation between two independently transcribed equations from different sections of the same source derivation.

**A discretization pathology avoided.** The source model documents (and this study independently confirmed) that an odd two-phase node count $N_1$ produces a mathematical pathology in the moving-boiling-boundary formulation. All results in this paper use even $N_1$ (specifically $N_1=16$ for all reported results; convergence with respect to $N_1$ was separately confirmed, with the codimension-2 point location changing negligibly from $N_1=16$ onward for the geometry used at Point A, and both genuine Bogdanov–Takens points, B and C, confirmed independent of $N_1$ to five decimal places at $N_1=2,4,8,16$, since the relevant eigenvalue coalescence occurs entirely within an $N_1$-independent sub-system).

**Nonlinear confirmation of linear stability results.** Direct time-domain integration of the full nonlinear dynamical system, from a small perturbation around a computed steady state, grows into a bounded limit-cycle oscillation exactly where the linearized Hopf analysis predicts a positive-real-part complex eigenvalue pair, and decays back to the steady state exactly where the linear analysis predicts stability — an independent, nonlinear confirmation of every linear stability result used in this paper.

## S3. The extraction-bug correction (Point B)

An early version of the surrogate boundary-extraction procedure (Section 4.3, main text) used a search bracket of fixed width, offset from the known fold value by a small fraction (e.g. $(\text{fold}\times1.001, \text{fold}\times1.6)$), and located the nearest zero-crossing of the surrogate's predicted stability indicator within that bracket. This occasionally located a **spurious** zero-crossing — introduced by the surrogate's own small-amplitude fitting imperfections, not a real physical feature — at a location that varied randomly between training seeds. This was confirmed, not assumed, by directly evaluating the ground-truth stability indicator at the exact same location for several affected seeds and finding, in every case, a single, clean, unambiguous crossing at the true boundary location — i.e., the extra crossing existed only in the surrogate's own imperfect fit, never in the physical model.

**Correction applied**: the search bracket is now centered on the already-known true boundary value (from the same ground-truth continuation used to generate training data) and progressively widened only if no crossing is found; when multiple crossings exist within a widened bracket, the one nearest the true value is selected. This is implemented in `src/tide/eval/bt_decoupling.py::_extract_surrogate_upper` and locked in with a regression test (`tests/test_bt_point.py`) using a synthetic surrogate constructed to have a known spurious root at a known wrong location, confirming the corrected procedure still recovers the true boundary.

**Effect of the correction on previously reported numbers.** This correction was applied before any of the numbers in the main text's Table 3 were computed; it is documented here because the *first* (uncorrected) version of the Point B primary result, obtained before this bug was found, reported a substantially larger apparent effect (upper-boundary ratio 10.2$\times$, versus the corrected 3.5$\times$ reported in the main text at matched training budget). Both numbers are disclosed here, transparently, rather than only reporting the corrected figure, since the direction and statistical significance of the core finding (decoupling exists and is severe near a genuine BT point) are unchanged by the correction — only the precise magnitude is affected.

## S4. Full statistical detail: pseudo-replication correction

An earlier version of the Point A analysis (Section 5.1, main text) treated each individual (seed, evaluation-point) pair as an independent sample when computing a Mann-Whitney U test between "near" and "far" boundary-error distributions. Because many evaluation points come from the *same* trained surrogate (same seed), and a given seed's surrogate can be uniformly better or worse across its entire domain, this treats correlated observations as independent, inflating apparent statistical significance. All results in the main text use the corrected procedure: one summary statistic (mean boundary error, near and far, separately) per seed, compared across seeds with a paired Wilcoxon signed-rank test — the seed, not the evaluation point, is the unit of replication throughout this paper.

## S4.5. The double-zero coordinate correction and the window-boundary correction (post-manuscript-draft audit)

An external audit of the full repository (code, tests, logs, source PDFs), performed after an initial manuscript draft, found two further errors, both now corrected and both independently re-verified (not merely re-reported from the audit) before being accepted:

**Coordinate correction.** The original method for locating Points B and C fixed $N_{pch}$ to the Eq. 26 algebraic fold value as a function of $N_{sub}$ and searched only along that curve for a coalescing-eigenvalue-pair sign change. Direct spectral evaluation at the resulting coordinates shows this is not a genuine double-zero point (Point B: eigenvalues +0.0439/−0.0451, not a repeated zero). Corrected by a direct, unconstrained 2D Newton solve (`src/tide/continuation/double_zero.py`) on the sum and product of the two smallest-magnitude eigenvalues (chosen over the raw eigenvalues themselves because sum/product remain smooth through the real-to-complex-conjugate branch point, where the raw eigenvalues are not differentiable and Newton on them directly diverges). Corrected coordinates: Point B (14.142794816, 20.597778032), Point C (7.630101792, 10.913202566), both converging to residual $<10^{-11}$ and re-confirmed $N_1$-independent. Checked directly: the gap between the fold curve and the true double-zero point does not close as $\Lambda \to 0$ (stabilizes at a small non-vanishing offset), so $\Lambda=0.001$ is a representative finite low-friction point, not a numerical stand-in for an exact zero-friction limit.

**Window-boundary correction.** `wedge_boundaries`'s `lower` return value was the Eq. 26 fold, documented as "indistinguishable from the true real-eigenvalue crossing to high precision." Direct scanning for the true $g=0$ root near the fold shows this is false close to the BT tip: at Point B, $N_{sub}=14.14$, the fold (20.590725) sits entirely outside the true window (20.592276–20.594954), overstating window width by ~58%. Corrected by `wedge_boundaries_true`, which scans for true sign changes directly rather than assuming the fold is one, using progressively narrower search radii to remain accurate as the window shrinks toward the BT tip.

**Downstream impact, checked directly rather than assumed:**
- The *upper* boundary value (used for every near/far statistic in Table 3–4) is identical between the original and corrected window-boundary computation to $10^{-9}$ — both share the same, always-correct upper-crossing bisection. **None of the paper's headline decoupling or fix-comparison numbers require recomputation.**
- The window-width scaling (Fig. 3) does require the correction: recomputed exponent is $1.00$ ($R^2>0.9999$, all 40 tested points valid) versus the original $0.96$ ($R^2=0.994$, several failed evaluations near the tip) — a materially cleaner result, not merely a corrected one.
- The mechanism-test correlation (Section 5.3) was re-run with the corrected window width across a 6-seed check: median $\rho=+0.668$, matching the originally-reported $+0.675$ closely. The correction affects measurement precision, not the mechanism-test conclusion.
- The shift in BT-point coordinates (~$10^{-5}$ in $N_{sub}$, ~$10^{-3}$ in $N_{pch}$ for Point B) is negligible relative to the $\pm0.5$-unit near/far window used throughout Section 5's statistical analysis.

**Separately, three related bisection-based root-finders** (`curves.hopf_npch`, `codim2_convergence.hopf_npch_general`, `bt_point_data._bisect_g`) were found by the same audit to mishandle an exact root at a bracket's lower endpoint (when `f_lo` is exactly zero, the shared bisection pattern always narrows toward the upper endpoint instead of returning the lower one). Fixed with an explicit endpoint check in all three. The full test suite (91 tests, including 10 new tests locking in both corrections and the endpoint fix) passes after all changes.

## S5. Reproducibility

All results in this paper were computed on a single laptop-class CPU (no GPU or HPC resources), using Python 3.13 and JAX 0.11.1 for automatic differentiation and JIT compilation. A full 20-seed decoupling comparison for one surrogate configuration (Table 3, main text) completes in 5–25 minutes depending on network size, on a single Apple M-series CPU. Complete code, including every regression test locking in the bug fixes and mechanism checks described in this Supplementary Material, is available at the repository referenced in the main text's Data and code availability statement.
